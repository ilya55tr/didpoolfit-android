# UserStorage — простое хранение аккаунтов

## Структура

Файл `SharedPreferences("users")`, два ключа:

- `list` — JSON со всеми аккаунтами, ключ каждого аккаунта — email в нижнем регистре.
- `currentEmail` — email вошедшего пользователя; после выхода ключ отсутствует.

```mermaid
flowchart TD
    P[SharedPreferences: users] --> L[list: JSON]
    P --> C[currentEmail]
    L --> A[alice@example.com]
    L --> B[bob@example.com]
    C -. выбирает профиль .-> A
    A --> D[Имя, телефон, email, обычный пароль, пол, дата рождения, вес, рост, фото]
    A --> H[history: массив запусков тренировок]
```

Пример содержимого `list`:

```json
{
  "alice@example.com": {
    "fullName": "Alice",
    "phoneNumber": "79991112233",
    "email": "alice@example.com",
    "password": "12345!@#",
    "gender": "Female",
    "dateOfBirth": 946684800000,
    "weight": 60.0,
    "height": 170,
    "photoFileName": "",
    "history": [
      {
        "title": "Fullbody Workout",
        "exercises": 8,
        "minutes": 17,
        "seed": 123,
        "startedAt": 1793700000000
      }
    ]
  }
}
```

Пароль хранится обычной строкой, как согласовано для учебного проекта. UUID,
хеширования, версии формата и переноса старых данных нет. Прежние `accounts` и `user`
не читаются: после перехода нужно зарегистрироваться заново.

## Методы и места вызова

| Метод | Что делает | Где вызывается |
| --- | --- | --- |
| `UserStorage(Context)` | Открывает файл `users`. | Экраны регистрации, входа, Splash, Home, Profile, Edit, Workout Details, Activity History. |
| `UserStorage(SharedPreferences)` | Использует отдельный файл теста. | `UserStorageTest`, `ProfilePhotosTest`. |
| `isPasswordValid()` | Проверяет 8 символов: 5–7 цифр и 1–3 ASCII-спецсимвола. | Первый шаг регистрации, форма Edit и проверка сохранения. |
| `hasUsers()` | Есть ли хотя бы один аккаунт. | Splash при выборе Welcome/Login. |
| `emailExists()` | Проверяет email без учёта регистра и пробелов по краям. | Проверка первого шага при вводе. |
| `phoneExists()` | Проверяет номер без форматирования среди всех аккаунтов. | Первый шаг при вводе и `register()`. |
| `register()` | Проверяет поля и дубликаты, добавляет профиль с пустой историей. Сессию не меняет. | Фоновая задача второго шага регистрации. |
| `login()` | Сравнивает email и обычный пароль, сохраняет `currentEmail`. | Фоновая задача Login. |
| `getCurrentUser()` | Возвращает профиль текущего пользователя или `null`. Пароль в объект `User` не передаёт. | Splash, `ProfileUi.requireUser()`, Edit. |
| `logout()` | Удаляет только `currentEmail`, сохраняя профили и историю. | Profile после подтверждения выхода. |
| `updateProfile()` | Обновляет имя, пол, дату рождения, рост, вес и фото. Для нового пароля проверяет текущий. | Edit после подтверждения сохранения. |
| `addWorkout()` | Добавляет событие запуска с названием, параметрами и временем нажатия кнопки. | Фоновая задача кнопки Start Workout в Workout Details. |
| `getHistory()` | Возвращает историю текущего пользователя, новые события первыми. | Activity History. |
| `readUsers()` | Читает JSON из `list`; повреждённые данные не заменяет пустым списком. | Операции чтения и изменения аккаунтов. |
| `saveUsers()` | Сохраняет весь JSON и проверяет результат `commit()`. | Регистрация, обновление профиля, добавление тренировки. |
| `normalizeEmail()` | Убирает крайние пробелы и приводит email к нижнему регистру. | Поиск, регистрация, вход. |
| `validProfile()` | Проверяет имя, пол, дату без будущего, вес 20–300 и рост 50–250. | Регистрация и обновление профиля. |
| `User(JSONObject)` | Собирает данные профиля из JSON для экрана. | `getCurrentUser()`. |
| `StorageException(Throwable)` | Передаёт ошибку чтения или записи экрану. | Внутренние операции хранилища. |

`RegistrationResult`: `SUCCESS`, `EMAIL_EXISTS`, `PHONE_EXISTS`, `INVALID_PROFILE`.
`UpdateResult`: `SUCCESS`, `INVALID_PROFILE`, `WRONG_PASSWORD`, `NO_SESSION`.

В `updateProfile()` и `addWorkout()` передаётся ожидаемый email. Если пользователь
успел выйти или сменился аккаунт, операция не изменит чужой профиль.
Общий `LOCK` защищает одновременные записи в одном процессе.

## Регистрация и история

Первый шаг регистрации передаёт данные во второй через Intent, ничего не сохраняет.
Аккаунт появляется только после успешного второго шага; далее открывается Login.
Вход, регистрация, запись профиля и истории выполняются в фоновых задачах.

История — записи о **запуске**, не о завершении тренировки. Каждое отдельное нажатие
Start Workout создаёт запись. Время фиксируется в момент нажатия, до фоновой записи.
`startedAt` и дата рождения хранятся в миллисекундах; дата рождения форматируется в UTC,
время тренировки показывается в часовом поясе устройства. `seed` позволяет открыть
тот же план упражнений из карточки истории.

Проверки находятся в `UserStorageTest`: два аккаунта, дубликаты, вход/выход, пароли,
дата рождения, отдельная история каждого аккаунта, сортировка и сохранение данных.
Тесты используют отдельные preferences.
